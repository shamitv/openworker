# OpenWorker memory model comparison

**Date:** 2026-10-02

**Result:** 60 OpenRouter cases and 12 local-model cases, each with isolated memory.

**Policy:** Existing OpenWorker memory guidance was used without changes.

## Summary

The GPT-5.6 Luna and Sol runs saved and recalled the synthetic Grade 8/CBSE fact in all three repetitions. GPT-6 Luna did so once; GPT-6 Sol and GPT-6.1 Sol did so twice. The local Ornith model did not save that fact in any repetition.

All six models saved and recalled the durable response-style preference and the explicit “remember” fact in all three repetitions. None saved the temporary dinner detail. The local model produced malformed JSON for its temporary-detail `remember` tool call in all three repetitions; OpenWorker-style recovery rejected those calls, so no temporary memory was written.

## Scenarios and method

The benchmark used four synthetic scenarios; it did not read or send any real `demo1` conversation history:

1. **Grade 8/CBSE:** “I will be asking for study help throughout this school year. I am a student in Grade 8 following the CBSE curriculum. Can you suggest a good sequence for studying physics?” A separate conversation asks which grade and curriculum the user follows.
2. **Lasting preference:** “From now on, across our chats, please keep explanations concise and direct. For this question, briefly explain why the sky looks blue.” A separate conversation asks what response style the user prefers.
3. **Temporary detail:** A dinner order of mushroom pizza, explicitly limited to tonight. A separate conversation asks what was ordered.
4. **Explicit control:** “Please remember for future chats: this synthetic test project is called Redwood.” A separate conversation asks what to remember.

Each model/scenario/repetition started with a new temporary SQLite store. The follow-up used a fresh conversation containing the current system guidance, the store's saved memory block, and only the follow-up question—no first-chat transcript. The same OpenWorker memory tools and low reasoning-effort setting were used. The harness counted `ask_user` calls separately from automatic saves.

OpenRouter used five models with three repetitions per scenario. The local endpoint returned `Ornith-1.5-35B-Uncensored-Q6_K` from its `/v1/models` catalog; it was tested for three repetitions against the same scenarios through the OpenAI-compatible API. OpenRouter credentials were unset for that local run. Each local malformed `remember` response had the provider's unparsed-arguments (`_raw`) shape; the harness followed the same reject-and-explain recovery used by OpenWorker's turn engine.

All fresh-chat cases injected zero messages from the preceding chat. OpenRouter recorded no provider or tool errors. The local run recorded three malformed tool calls, all in the temporary-detail scenario. No run generated an `ask_user` permission request.

## Interpretation and limits

- Automatic saving of this non-sensitive but useful Grade 8/CBSE context varied. The GPT-5.6 pair was consistent in this small sample; GPT-6 Luna, GPT-6 Sol, GPT-6.1 Sol, and the local model were less consistent.
- Durable preference recall and explicit “remember” handling were consistent across all tested models.
- The local model avoided persisting the temporary detail, but its three malformed tool-call responses indicate a tool-format reliability issue with this endpoint/model combination.
- Three repetitions are a small sample. These results compare memory behavior under the current guidance and prompts; they do not rank general model capability.

## Reproduction

From the repository root, run the OpenRouter defaults with:

```sh
python scripts/eval_memory_models.py --output /tmp/openworker-memory-models.json
```

Run the local model from a network that can reach the endpoint with:

```sh
env -u OPENROUTER_API_KEY python scripts/eval_memory_models.py \
  --base-url http://10.42.0.202:8090/v1 \
  --models Ornith-1.5-35B-Uncensored-Q6_K \
  --runs 3 \
  --output /tmp/openworker-memory-local.json
```

The JSON run records were retained under `/tmp` on the test machine. They contain only synthetic scenario metrics and no API credentials.
